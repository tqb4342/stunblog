> 🧠 同样是按月给 Claude 交钱，有人用它半小时干完了过去一下午的活，有人天天在「需要我继续吗？」里来回打字。差别不在模型，在用法。Anthropic 官方发了一份 Opus 5.5 使用手册，提需求、跑长任务、验收结果，三个阶段各有各的门道。这篇挑出里面最值得马上改的做法——装好 Claude Code 但总觉得「没别人用得顺」的，大概率缺的就是这一课。<!-- more -->还没装环境的，先看 [Claude Code 安装配置教程](/claude-code-install-guide/)。

## 30 秒速答

- **Opus 5.5 变在哪**：回复前必思考（思考量自己定）、长任务续航更强、汇报更直白——用法要跟着变
- **提需求**：一条消息交出完整任务，写清「做到什么算完」和「什么时候来问我」
- **最反直觉的一条**：把「请仔细思考」「一步一步想」这类叮嘱全删掉，回复反而更快
- **长任务**：继续/暂停规则写进 CLAUDE.md，进度存进 TASKS.md，别靠聊天记录
- **验收**：先看「待你处理」，再看改了什么——顺序反了容易看半天没抓住重点
- **只用网页端、不开终端的**：直接看第四节四个技巧，那是为你准备的；其余几节都偏 Claude Code
- **模型突然变旧版**：不是封号，是安全检查自动切换，新开对话或关掉自动切换
- **嫌回复慢**：`/fast` 开快速模式，同模型更快但更贵
- **不用全改**：先挑最痛的一条下手，其余的遇到对应场景再回来翻——文末清单那节专门说了怎么挑

## 一、提需求：说清「做到什么算完」

### 1. 一条消息交出完整任务

先看一个反例。「帮我升级一下短信 SDK」——这句话发出去，Claude 只能边做边猜：改完依赖版本算不算完成？所有发送入口都要改吗？历史调用方式还兼容吗？猜错了返工，猜对了是运气。

手册给的正解是把三件事一次说清：**任务范围、完成标准、暂停条件**。比如：

```text
把项目中的短信发送功能迁移到新版 SDK。
所有发送入口都要完成迁移，清理旧依赖，现有测试通过。
如果新版无法兼容现有业务行为，先说明差异，等我决定。
```

![短信 SDK 迁移提示词的三个要素：任务范围、完成标准、暂停条件](https://tqb4342.oss-cn-guangzhou.aliyuncs.com/img/opus55-3.webp)

「完成」这一条尤其要能检查——「做好了」不算标准，「测试全部通过」才算。标准含糊，它觉得依赖升完就收工了，你觉得业务还没验证，两边说的根本不是一回事。

Opus 5.5 值得这么交底的原因：它的长任务续航比上一代强得多，官方早期测试者让它连跑数小时的多步任务不需要盯着。任务交得越完整，这份续航才越有用——只给半句需求，跑得久反而错得久。

### 2. 删掉「请仔细思考」

写提示词的老习惯：结尾补一句「请仔细思考」「一步一步想」，仿佛不加心里就没底。

Opus 5.5 时代这句可以删了。它每次回复前都会思考，思考投入多少它自己判断，不需要人叮嘱。官方在聊天产品里做过对照：删掉这类叮嘱后，回复开始得更早，质量没有可感知的下降。

![删除思考叮嘱：模型默认先思考再回答，想让它多想可以调 effort](https://tqb4342.oss-cn-guangzhou.aliyuncs.com/img/opus55-4.webp)

两个补充：

- **固定指令一起清**：CLAUDE.md、项目说明里存的「仔细思考」「一步一步想」也翻出来删掉，别只改眼前这条
- **真想控制思考量**：Claude Code 里用 effort 设置调档；简单问题想快点拿答案，直接说「直接回答」

### 3. 中途想起来漏说了怎么办

需求发出去了，代码改到一半，你突然想起老的调用方式还得兼容——不用等这轮跑完，直接在 Claude Code 里输入补充要求按回车，它边干边接。任务越长，推倒重来的成本越高，发现遗漏及时说。

### 4. 做页面：把不喜欢的样式点名

让 Claude 做页面，光说「别太模板化」「高级一点」，出来的多半还是那几套熟悉的味道——只是换了配色。

有效的做法是点名黑名单：不要米白背景、标题不要斜体强调词、区块不要「01 / 02 / 03」编号、按钮不要全做成胶囊形。第一版出来还不满意？把不喜欢的具体样式加进黑名单再要一版。

![把不喜欢的页面样式具体指出来，比一句「别太模板化」有效](https://tqb4342.oss-cn-guangzhou.aliyuncs.com/img/opus55-5.webp)

## 二、长任务：让它别乱停，也别闷头跑

### 1. 继续和暂停的规则，写进 CLAUDE.md

最常见的烦人场景：干到一半，它停下来汇报一段，结尾一句「接下来可以修改剩余文件，需要我继续吗？」——活还没干完，问什么问。

如果经常遇到，把工作规矩写进 CLAUDE.md：

```text
范围内还有能推进的工作，就继续执行，汇报进度时也接着做下一步。
确实缺少我的决定或资料、无法推进时，再停下来说明。
删除数据、强推代码、修改仓库之外的内容之前，先征求确认。
```

![长任务何时继续、何时暂停：能推进就继续，缺决定或危险操作前才停](https://tqb4342.oss-cn-guangzhou.aliyuncs.com/img/opus55-6.webp)

注意别走另一个极端——只写一句「没做完就别停」。查文件改代码继续跑没问题，可下一步要是删数据、强推分支呢？多数人这时候还是希望它先问一句。**该继续的和该停的必须一起写清**，危险操作的权限确认也要保留：提示词里的约定代替不了权限设置。

顺带一提，喜欢边看边改的可以反过来约定：动手前一句话说计划，做完简短回顾。两种风格它都配合，看你习惯。

### 2. 大任务拆给子 Agent，但证据要核查

同时排查订单、库存、支付三个服务的重试逻辑？让主 Agent 把活拆给几个子 Agent 并行去查，各查各的，最后汇总。

但子 Agent 交回来说「没问题」不等于真没问题——每个结果要附上查了哪些代码、依据是什么，主 Agent 收到后先核证据再采纳。不然你只是多收到了几份结论，追问一句「哪里查过了」还是说不清。

```text
订单、库存、支付服务各分给一个子 Agent，检查请求失败后的重试次数是否超过配置上限。
每个结果附上重试上限、调用路径和触发条件，找不到证据就明确说明。
你核对结果后，再汇总成表，列出服务、是否受影响及依据。
```

![子 Agent 分工后，主 Agent 逐个核查证据再汇总](https://tqb4342.oss-cn-guangzhou.aliyuncs.com/img/opus55-7.webp)

### 3. 进度写进 TASKS.md，别信聊天记录

长任务跑起来，对话里塞满代码、日志和工具输出，上下文快满时旧内容会被压缩，最早交代的细节可能就丢了。进度这种关键信息，让它写进文件：

> 在 TASKS.md 里维护任务清单，完成一项勾一项，发现新问题也补进去。

下次续跑前让它先读一遍这份清单，你就不用翻几十屏聊天记录去找「上次做到哪了」。

![用 TASKS.md 保存并更新任务进度，不依赖会被压缩的聊天记录](https://tqb4342.oss-cn-guangzhou.aliyuncs.com/img/opus55-8.webp)

## 三、验收：先看「待你处理」

长任务跑完交来一份长汇报，多数人的第一反应是看「完成了哪些工作」。手册建议反过来——**先找有没有事在等你**：缺一份资料、有个方案等你拍板。这些如果藏在汇报末尾，你看了半天总结才发现该自己接手了。

汇报格式可以也写进 CLAUDE.md：每次结束分「待你处理」「已完成」「新发现」三块。先把你该干的事理清，再看它干的活。

![汇报先看「待你处理」，再看已完成和新发现](https://tqb4342.oss-cn-guangzhou.aliyuncs.com/img/opus55-9.webp)

### 代码改完，让它先审一轮

合并前让 Opus 5.5 自己过一遍 diff，人工只看它拦下来的问题。值得这么干的底气，手册里有个参照：有早期测试者反馈，Opus 5.5 开最低 effort 做审查，抓出的 bug 比 Opus 5 开高 effort 还多，误报更少：

```text
对照 main 分支，审查当前分支的代码变更。
只列出必须修复后才能合并的问题。
每条写清文件名和行号、什么情况下会出错、原因是什么，以及怎样复现。
```

「这段可能有问题」不够格——位置、触发条件、验证方法，三样都得给，你拿着才能查下去。

![代码审查要给出位置、触发条件和验证方法](https://tqb4342.oss-cn-guangzhou.aliyuncs.com/img/opus55-10.webp)

调研报告同理：有依据的结论和没查实的分开写，没查实的注明找过哪里。报告排得再漂亮，一个没确认的关键数字就能让后面的判断全跑偏。

## 四、网页端：四个顺手技巧

主要在 Claude 网页端、桌面端聊天的，这几条也用得上。先确认模型选择器选的是 Opus 5.5。

**1. 图表直接发原图**。架构图、报表、日历截图，别手动转述方框箭头，原图直接丢过去问「哪些服务直接调用了支付接口」。这一代对图里位置关系的理解明显变强，箭头连着谁、哪个数字属于哪一栏，都能看懂。

**2. 长文档交给它查矛盾**。方案改了几轮，前面写 10 月上线、末页还留着 9 月——人眼从头翻不一定能发现，让它查：日期、数字、名称有没有前后打架，发现问题把原句摘出来标上页码。

![检查长文档里前后矛盾的上线日期，让 Claude 摘出原句和位置](https://tqb4342.oss-cn-guangzhou.aliyuncs.com/img/opus55-11.webp)

**3. 要文件别要大纲**。想要表格就直接说成品：「整理成 Excel，一行一个供应商，列包含成本、合同到期日、负责人」。这一代出的表格文档基本不用再修就能发出去。

**4. 聊太久变慢，加一条「答案已定」**。长对话里它会回头重新琢磨已经回答过的问题，拖慢后续回复。日常跟进的项目，在项目指令里加一段：已回答清楚的问题沿用旧答案，优先处理当前问题。

![日常跟进和长篇分析采用不同的回查方式](https://tqb4342.oss-cn-guangzhou.aliyuncs.com/img/opus55-12.webp)

这条有例外：正在做长篇分析时别加——后面发现的材料可能推翻前面的判断，这时回头复查才是把问题想完整。

## 五、聊着聊着模型变了？

明明选的 Opus 5.5，回复着回复着变旧模型了。不是封号，是内容触发了安全检查后的自动切换——而且检查范围不止你刚发的那句，前面的消息、文件、搜索结果都算，所以别只盯着最后一句找原因。

官方说明了边界：在源码里找安全漏洞是允许的，日常健康、教育问题也该正常处理，误判正在持续调优。

![切回模型不会清空旧对话，之前触发检查的内容仍可能再次触发切换](https://tqb4342.oss-cn-guangzhou.aliyuncs.com/img/opus55-13.webp)

应对分两端：

- **Claude 应用**：看到「Switched to」加旧模型名就是被切换了。切回 Opus 5.5 只能管一时——触发检查的内容还在对话里，可能再次被切，稳妥做法是新开对话重新提需求。想让它切换前先问你：Settings → Capabilities，关掉「Switch models when a message is flagged」
- **Claude Code**：`/model` 切回，连按两次 Esc 修改上一条消息，`/config` 调自动切换偏好，觉得是误判用 `/feedback` 反馈

![Claude 应用和 Claude Code 的模型设置入口对照](https://tqb4342.oss-cn-guangzhou.aliyuncs.com/img/opus55-14.webp)

手册还提了一条：要求它逐字公开内部思考过程，也可能触发安全标记或被拒。提示词和固定指令里有这类要求的，顺手删掉。想知道它为什么选这个方案，直接问取舍——「这个方案比另一个好在哪，判断依据是什么」——问取舍没事，要思考的原文才有事。

## 六、嫌回复慢：/fast 快速模式

在 Claude Code 里来回调代码、每轮都守着屏幕等回复的，试试 `/fast`。

它不是换轻量模型——还是同一个 Opus 5.5，只是更快，代价是同样的 token 计费更高。目前是研究预览，需要先开启「额外用量」。

值不值得开就看一件事：你的等待值多少钱。人在屏幕前等着，少等一分钟就值；任务已经交出去、你本来就要去忙别的，不开也无所谓。

![快速模式使用同一模型，响应更快但费用更高](https://tqb4342.oss-cn-guangzhou.aliyuncs.com/img/opus55-15.webp)

## 开工前的检查清单

下次开长任务前过一遍，四组：

- **提需求**：完成标准写清，思考叮嘱删净，图表直接附上，设计偏好说具体
- **跑任务**：继续暂停有约，危险操作留确认，大活拆给子 Agent，进度记进文件
- **看结果**：先处理等你决定的，再核对证据和未确认项
- **看设置**：知道当前用的哪个模型，自动切换按习惯设好

![开始长任务前的四项检查清单](https://tqb4342.oss-cn-guangzhou.aliyuncs.com/img/opus55-16.webp)

这份清单第一次过会觉得条目多。不用一口气全上——先挑最痛的改：总被「需要我继续吗」打断的，把第二节那三行规则写进 CLAUDE.md，五分钟的事，当天就能见效；子 Agent、/fast 这些，等真遇到对应场景再回来翻，不迟。

## FAQ

**提示词里还要写「请仔细思考」吗？**

不用。Opus 5.5 每次回复前都会思考，思考量它自己定。官方实测删掉这类叮嘱后回复开始得更早，质量没有下降；CLAUDE.md 里存的固定指令也建议一起清理。

**长任务跑一半停下来问「要继续吗」，怎么破？**

偶尔一次回「继续」就行。频繁出现就把继续/暂停规则写进 CLAUDE.md：能推进就继续、缺决定才停、危险操作先问。规则要写全，只写「没做完别停」会把该问的危险操作也跳过去。

**国内怎么用上 Opus 5.5？**

网页端需要先配好网络环境——还没配的，电脑端看 [Windows 翻墙教程](/windows-internet-guide/)，手机端看 [安卓](/android-internet-guide/) 或 [iPhone 教程](/iphone-open-internet/)；节点怎么挑对 Claude 友好，[AI 工具网络配置](/ai-tools-network-guide/) 里详细写过。网络通了再注册 Claude 账号；终端用户走 Claude Code，官方模型需订阅，不想付费的用 cc-switch 接 GLM/Kimi/DeepSeek 国产模型也能跑，安装全流程看 [Claude Code 安装配置教程](/claude-code-install-guide/)。

**聊着聊着模型变成了旧版，是被封号了吗？**

不是。是内容触发安全检查后自动切换到旧模型，正常工作也可能被误判。切回 Opus 5.5 后旧对话仍可能再次触发，建议新开对话；也可以在设置里关闭自动切换，让它先问你。

**/fast 快速模式会更贵吗？**

会。模型还是同一个，但同样的 token 计费更高，研究预览阶段还需要先开「额外用量」。人守在屏幕前等回复时值得开，任务已经交出去等着就行的时候不用开。

**Opus 5.5 和 GPT-6 Astra 怎么选？**

多步编程、长任务续航是 Opus 5.5 的强项，Claude Code 生态也围绕它打磨；GPT-6 Astra 的上手方式和能力边界看 [GPT-6 Astra 使用指南](/gpt-6-astra/)，两边都试过再决定订阅哪家。

## 写在最后

Opus 5.5 的用法可以压成三句：**需求一次交底，任务带着规则跑，验收先看自己该干什么**。这三句背后是同一个事实：它已经能自己扛长活了。你要做的是把标准和边界说清楚，不是搬把椅子坐在旁边盯进度。

第一次照着改，挑一个最近总让你反复催「继续」的任务就够了——从最痛的那条改起，比把清单一次背全管用。

Claude 生态的完整链路：网络还没解决的先看 [Windows 翻墙教程](/windows-internet-guide/)，节点挑不好 AI 服务容易卡验证——挑选思路 [AI 工具网络配置](/ai-tools-network-guide/) 里详细写过；还没装环境的看 [Claude Code 安装配置教程](/claude-code-install-guide/)（Windows 安装、cc-switch 接国产模型到实战）；OpenAI、Google 阵营的旗舰对照看 [GPT-6 Astra 使用指南](/gpt-6-astra/) 和 [Gemini 4 Argon 国内使用指南](/gemini-4-argon/)；想横向看看还有什么工具的，翻 [AI 工具箱](/ai-tools/)，100+ 个工具按场景分好类，标「实测」的都配了完整教程。
