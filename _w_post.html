Headscale + Tailscale 自建私有网络

目标：官方 Tailscale 免费版有设备数量限制，且控制面在境外，本文以 Headscale 作为自建控制面，Tailscale Client 负责节点接入与 WireGuard 加密通信，Headplane 提供 Web 管理界面，实现自主可控的跨网络组网，且所有设备和数据都由自己掌控。

效果：让分散在不同地点、不同内网、没有公网 IP 的机器，像在同一个局域网里一样互相访问（SSH、HTTP、任意 TCP/UDP），流量全程 WireGuard 端到端加密。

文档信息

架构与端口规划

两条链路必须分清：

① 控制面 ② 数据面
谁和谁 节点 ↔ headscale 节点 ↔ 节点
干什么 注册、下发网络拓扑、交换公钥、协调打洞 你的真实业务流量（SSH、HTTP…）
走什么 TCP 8080（公网经 NAT 变 28080） UDP，端口动态
加密 Noise 协议 WireGuard

关键性质：headscale 挂了，已经建立的节点间直连不受影响，业务照常跑；只有新节点注册和拓扑变更会失败。

三个组件

组件 作用 本方案版本
Headscale 自建控制面，替代 Tailscale 官方协调服务器。管节点注册、分配 100.64.x 地址、下发拓扑 v0.29.4
Tailscale 客户端 跑在每台要入网的机器上，建立 WireGuard 隧道 1.102.5
Headplane 第三方 Web 管理界面（Headscale 官方没有 UI）。看节点、发密钥、管用户 v0.7.1

端口清单

端口 协议 绑定地址 用途 是否需对外
8080 TCP 0.0.0.0 headscale 控制面 跨网络接入时需要（经 NAT 映射）
9090 TCP 127.0.0.1 headscale metrics/debug 否
3000 TCP 0.0.0.0 Headplane Web UI 见 [HeadPlane Web](#部署 Headplane Web 管理界面)
41641 UDP — WireGuard 节点间数据面 打洞失败时需映射
3478 UDP — STUN（启用自建 DERP 时才用） 启用 DERP 时需要
80 / 443 TCP — Let’s Encrypt 签发证书 上 TLS 时需要

配置项 值 为什么
server_url 公网 DDNS + NAT 端口 headscale 对外宣告的地址，会出现在客户端注册 URL 里。必须是所有客户端都能访问到的地址

database.sqlite.path /var/lib/headscale/db.sqlite 数据库文件
unix_socket /var/run/headscale/headscale.sock CLI 通信套接字，权限 0770
dns.base_domain example.com 占位值，需修改。决定 MagicDNS 后缀
tls_cert_path / tls_key_path "" 留空则纯 HTTP
acme_email / tls_letsencrypt_hostname "" Let’s Encrypt 自动签发
policy.mode file ACL 策略模式
policy.path "" 空 = 不加载 ACL = 默认全通。这是合法值，不会报错
derp.server.enabled false 内嵌 DERP 中继要求 server_url 是 HTTPS，明文 HTTP 下开启会配置校验失败
derp.urls 官方 derpmap 默认会用 Tailscale 官方公共中继兜底，见 DERP
derp.auto_update_enabled true 每 3h 刷新官方地图

server_url 和 listen_addr 是两个不同的东西，端口号不一样是正常的（8080 vs 28080），因为中间隔了一层 NAT 端口转换。

部署 Tailscale 节点容器

由于我们需要让这台物理机能够SSH到组网内的任意一台设备上，所以需要选择 host 模式，让控制面宿主机自身进入 tailnet，成为 tailnet 成员

host 模式节点

参数 为什么必须
--network host 使用宿主机网络
--cap-add NET_ADMIN 创建和配置 TUN 设备需要
--cap-add SYS_MODULE 加载内核模块（配合 TUN）
--device /dev/net/tun 把宿主机 TUN 设备透传进容器。缺了会报 No such device
TS_USERSPACE=false 必须显式设置。默认 true 会启动 tailscaled --tun=userspace-networking，不创建真实的 tailscale0，做不了真正的 WireGuard 隧道
TS_EXTRA_ARGS 放 tailscale up 的参数。--login-server / --hostname / --accept-routes 都属于 tailscale up
--login-server 必须改成宿主机 IP 或公网地址，host 模式下容器共享宿主机网络命名空间，Docker 内嵌 DNS（127.0.0.11）不再可用，容器名解析不了
-v ts-host-state:/var/lib/tailscale 节点身份持久化。有了它，容器重建/重启不需要重新用密钥注册

host 模式让宿主机成为 tailnet 成员，意味着宿主机上所有监听 0.0.0.0 的服务都对全部 tailnet 成员可见。

关注这几个字段：

字段 含义
UDP 必须为 true，否则完全无法打洞，只能走中继
MappingVariesByDestIP false = 端点无关映射（EIM），打洞成功率高；
true = 对称 NAT，打洞基本必败，只能走中继
PortMapping 有 UPnP/NAT-PMP/PCP 会提高成功率，为空也没关系
Nearest DERP 最近的公共中继

按诊断结果处置：

诊断 处置
UDP: false 网络禁 UDP，检查防火墙/运营商策略，这种情况无法直连
MappingVariesByDestIP: false + PortMapping: UPnP 条件最好，通常自动直连成功，无需任何额外配置
PortMapping 为空 + EIM 通常仍能自动直连，无需额外配置
MappingVariesByDestIP: true（对称 NAT） 在路由器上映射 UDP 41641（或 tailscaled 实际端口）到该机器，或改用有公网 IP 的一侧主动连
无 UPnP 手动在路由器映射 UDP 端口

安全注意事项

控制面是明文 HTTP

当前 server_url: http://...，控制面流量（注册、下发拓扑、交换公钥）走明文。虽然 Noise 协议加密了实际内容，但还是建议上 TLS，见 [TLS](#上 TLS)。

Headplane 的暴露面

Headplane 绑定 0.0.0.0:3000，局域网内任何人都能打开登录页。API key 泄露 就能 完全控制 headscale。

建议：

  • 生产环境上 TLS 反代 + HTTP Basic Auth 或 OIDC

  • 或者只绑本机回环，通过 SSH 隧道访问：

    • 把 Headscale 部署时的 docker run 里的 -p 0.0.0.0:3000:3000 改成 -p 127.0.0.1:3000:3000
    • 同步把 headplane 配置里的 base_url 改成 http://localhost:3000，否则 cookie 域不匹配，登录后跳转异常。

  • API key 有效期不要设太长（本文用 90 天，生产建议 30 天）

Docker socket 挂载的风险

Headplane 挂载了 /var/run/docker.sock，意味着它可以完全控制宿主机上的所有容器。可以：

  • 启动特权容器挂载宿主机根目录
  • 读取其他容器的敏感数据
  • 停止 / 重启任意服务

建议（按安全强度递增）：

  1. API key 设短有效期，监控 Headplane 容器异常行为
  2. 直接关掉 Docker 集成：integration.docker.enabled: false 并去掉 docker.sock 挂载。代价是 UI 里不能重启容器、不能改 DNS，但节点/用户/密钥管理全部照常可用

修改 MagicDNS 后缀

当前 base_domain: example.com 是占位值。

example.com 是真实存在的公网域名。 用它作 MagicDNS 后缀意味着 tailnet 内部对 *.example.com 的解析会被劫持到 tailnet。虽然本方案下 --accept-dns=false、MagicDNS 实际不生效，但如果你将来开启 accept-dns，就会撞上这个冲突。

生产环境建议换成不会与公网冲突的后缀，如 tailnet.internal。修改后所有节点需重新注册。
